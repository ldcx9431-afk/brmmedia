# Homepage media preview performance fix (2026-10-10)

The homepage HTML/config were fast (about 0.01 seconds inside WSL and 0.08–0.11 seconds from the LAN client). The browser nevertheless mounted 19 video elements with `preload=metadata`, including previews in the hidden asset library. They issued 38 original-video media requests; some took 5–6 seconds. Several PNG frames/image originals were 0.5–3.5 MB each and competed with initial UI requests.

The dashboard and library now render lazy-loading compact JPEG previews instead of video elements or original images. The existing media-open action fetches the original video only when clicked; download links still target originals. The single background FFmpeg worker creates aspect-preserving previews bounded by 480×320 pixels with one encoding thread, publishes only successful nonempty output atomically, and uses versioned cache paths to avoid reusing the old large PNG frames. Audio waveform previews are retained. Asset collection stops at its configured display limit instead of validating all remaining history files.

Verification: 35 task-queue tests passed, including preview markup preserving original playback/download references without eagerly loading originals. The actual production Python environment passed compilation, UI construction and queue rendering. Deployment waited for an empty ComfyUI queue and backed up the active release file and Nginx site before restarting `baorong-backend` (this also warmed up ComfyUI; the short 502 interval ended once it was ready). Qwen was not restarted.

Browser acceptance after thumbnail warmup: 34 preview image elements, about 476 KB transferred for compact previews, zero original-video media requests before clicking; no resource requests exceeding two seconds in the first post-deploy sample. Clicking a video produced one original-video request and a decoded player with `readyState=4` and advancing playback time. These are samples from the tested LAN/browser, not fixed load-time guarantees. Media REST health and Qwen health returned OK; backend, LAN API, Qwen and Nginx were active.
